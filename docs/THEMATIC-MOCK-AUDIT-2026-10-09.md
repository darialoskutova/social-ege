## Версионирование и отправка файлов

- Текущая версия: `2027-draft-v1`; стабильные `mock_id` не зависят от имени файла.
- Submission сохраняет `mock_id`, `mock_version` и снимок метаданных пробника. DOCX каждой редакции находится в отдельной папке версии (`пробные варианты/2027-draft-v1`), поэтому следующая версия не изменит старую сдачу, её файл и максимальный балл.
- До этой переработки сохранённых попыток пробников в базе не было; существующие результаты онлайн-тестов и ДЗ не изменяются.
- Миграция `005_file_and_mock_submissions.sql` создаёт `mock_submissions` и добавляет ревизии/время обновления для ДЗ.
- PDF/JPEG/PNG до 15 МБ записываются под случайным UUID вне public root. Расширение, MIME и сигнатура проверяются; исходное имя хранится только как metadata.
- Ученик скачивает только собственный файл через сессионный endpoint. Преподаватель видит «Работы по пробникам» и скачивает файл через endpoint с ролью `admin`.
- Пока статус `submitted`, повторная отправка заменяет текущий файл и увеличивает `file_revision`. После перехода на проверку замена возвращает конфликт и не перезаписывает работу.

## Автоматические проверки

Validator проверяет разделы, 25 уникальных позиций, схему баллов, сумму 58, наличие source metadata, отсутствие дублей, разрешённые темы, единую группу 17–18, versioning и соответствие backend-каталога публичному manifest.

Интеграционный тест загрузок проверяет: 401 без сессии, владельца из session, игнорирование поддельного user ID, запрет чужого скачивания, admin download, сохранение после нового GET, версию пробника, замену, блокировку после начала проверки, MIME/сигнатуру, лимит размера, path traversal и реальную загрузку ДЗ.
